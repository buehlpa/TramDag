## Notes

- The original continuous NLL uses h = mean_k(B_k theta_k) but h' = sum_k(B'_k dtheta_k), i.e. the derivative is 20/19 times too large inside the scaling range [5%, 95% quantile]. Every observation inside that range therefore gets a constant -log(20/19) = -0.051 in its NLL (the tails are consistent). The term does not depend on the parameters, so gradients and fitted models are unaffected; the JAX engine keeps it for comparability with the published numbers.
- Notebook 'Continous_3_vars_linear_DGP_CS' printed td_model.nll() values (x1 = 2.12, x2 = 3.07) that do not match its own stored training histories (x1 = -0.57, x2 = 0.35); they come from an earlier/different model state, so that experiment is compared against the stored histories instead.
- R reference values are quoted from the comments in Mixed_3_vars_linear_DGP_LS.ipynb (Colr / polr fits). x1 and x2 are generated identically in all four experiments, so Colr(x2 ~ x1) applies to each of them.
- Sampling: the original engine inverts h with 100 float32 Chandrupatla iterations started from [-1e5, 1e5]. On the trained 6.1 models 2-4% of the samples stop with a residual |h(x) - u| > 1e-3 (max 0.5), which moves those samples by up to 3.5% of the variable range (mean 1e-4). The JAX engine inverts the linear tails in closed form and bisects the Bernstein part (residual < 1e-5), see tests/test_parity_torch.py.
- Coefficient differences between JAX, torch and R are within the sampling uncertainty: the standard error of ls(x1) in h(x2|x1) is about sqrt(3 / (n Var(x1))) = 0.024 for n = 80 000, and Adam with a constant learning rate of 0.01 leaves the last iterate fluctuating at that scale. R's Colr also uses a different Bernstein basis (order 6 on the data range), so it is a reference, not the identical model.
- Torch timings use the original code path of the notebooks (DataLoader with per-row __getitem__, num_workers=8) on CPU; the notebooks were also run with device='cpu'.
